# API 余额与本次用量

展示更新（2026-10-21）：按用户要求，正文开头仅显示“今日余额”和“这次花费额度”两项；无法查询或可靠计算时统一显示“未查询”。结束快照查询失败时不把旧余额冒充本次余额。运行时间、查询状态、账户变化、历史快照时间、完整性说明等仍保存在原有回执中，不在正文开头展开。以下涉及旧版详细展示的说明以此更新为准。

本功能直接接在现有 `daily` 与 `daily_brief` 中，继续使用每日北京时间 12:00 的 `PaperObsidianLocal-AI-ML`，无新增计划任务。余额接口与计价文档于 2026-10-21 核实：

- [DeepSeek 官方余额接口](https://api-docs.deepseek.com/api/get-user-balance/)：`GET https://api.deepseek.com/user/balance`，Bearer 认证；读取 `is_available` 以及每种币种的 `currency / total_balance / granted_balance / topped_up_balance`，金额按 Decimal 保存、计算。
- [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing)：当前含缓存命中、未命中、输出及峰谷时段计价，另有中国节假日条件，且价格可能调整。本功能不使用记忆单价，不自动抓价、不切换模型、不换汇。

## 运行与回执

一次 `daily` 对应 SQLite `runs.id`（以字符串 `run_id` 写入回执），同日重跑有不同 ID。新增总结、分段提取、审校、修订请求，以及翻译工具实际请求，沿用 `daily-api/*/attempts.json`、`daily-translation/*/requests.json`，补充 run_id、唯一 request_id、脱敏 source_id、请求模型。历史请求不补造 run_id。缓存命中不新增请求回执，也不把旧费用分摊给新运行。

余额与估算回执位于 `data/production/daily-runs/<run_id>.api.json`，运行报告继续保存在 `<run_id>.json`、SQLite、`last-run.json`。开始前保存 `running / ended=null` 并查询余额，正常处理收尾（含部分失败）后再次查询、保存；意外终止保留未完成状态。下次发现未正常收尾的运行，仅记录恢复检测时间，不冒充真实结束时间。余额处理异常不覆盖论文处理的原始错误。

每个来源每次运行前后各查一次，短连接/读取超时与 WSL 总时限，不重试、不重定向。只将 HTTPS 官方 DeepSeek 配置的凭据发送到固定官方接口。相同凭据的总结与翻译配置共用一次查询；不同凭据分别列配置来源，不推断为两个账户，不合计余额或差额。密钥变动会产生不同 source_id，旧快照不混用。成功快照另保存在现有 SQLite state，失败时可读取，但正文明确标为历史值并保留原时间。

本次运行仅按相同来源、相同币种比较 total_balance。余额增加显示“余额增加”。缺一侧或缺少对应币种时不可计算；不填 0，不取绝对值冒充消费。账户变化可能包含其他调用、充值、赠送或到账延迟，不是任务精确账单。

简报最开头使用最新一次 daily 的运行信息；论文交付仍由原有稳定 ID 与交付事件累计。离线重放只读已存余额，不创建在线运行或访问接口，余额标为“历史快照”并保留原始查询时间。打开或渲染 Markdown 不触发任何联网。

## 费用估算的边界

只读取属于本 run_id 的实际请求回执，以唯一 request_id 去重。每个请求必须有完整的缓存命中输入、未命中输入、输出 token 数，且缓存两项之和等于总输入；超时、结果未知、缺失 usage 均不能当成免费。翻译启动前写入本次执行记录，回收后核对 worker 的本次网络请求数；执行未收尾或回执数量不吻合时，本次总费用不可用。已返回完整 usage 的截断/无效内容仍可计费，与内容是否成功分开。

当前生产配置未设置可用单价。默认显示“本次费用暂无法准确计算”；已有可靠部分只保存在回执 `known_subtotals`，不作为本次总费用显示。明确核对无新增付费请求时才显示 0。不会累计多个来源可能重叠的余额差，也不新增今日累计费用。

如需启用特定时段估算，在现有 config.toml 增加明确价格配置。以下仅为字段模板，不是可直接启用的实际单价：

```toml
[[api_accounting.prices]]
source_id = "从本地脱敏回执取得的来源ID"
model = "实际请求的模型名"
currency = "CNY" # 或 USD，不自动兑换
cache_hit = "已核实的每百万缓存命中输入价格"
cache_miss = "已核实的每百万缓存未命中输入价格"
output = "已核实的每百万输出价格"
source = "明确计价来源URL或配置依据"
checked_at = "核实时间"
valid_from = "包含时区的ISO开始时间"
valid_until = "包含时区的ISO结束时间"
```

要求请求开始和结束均落在唯一匹配的价格区间；未知模型、缺少单价、重叠配置、跨价格区间均使估算不可用。调用者需明确该区间对应的峰谷、节假日、账户币种、模型实际价格，不能以文档核实日期冒充永久适用期。费用按 `(命中输入×命中价 + 未命中输入×未命中价 + 输出×输出价) / 1,000,000` 精确十进制计算，保留原精度。

## 验证

隔离测试：现有 WSL 环境中执行 `.venv/bin/python -m unittest discover -s tests`。`tests/test_api_accounting.py` 使用 MockTransport、临时 Vault/SQLite，验证余额/币种/失败、运行归属、费用完整性、离线零网络、缓存、同日累计成果和异常恢复。

`tools/verify_api_accounting.py` 是本次验收工具，不是新任务：核对 Windows 翻译配置与 WSL 来源，取得一次只读余额验证快照，通过现有 daily_brief 更新已存在的简报；不新增 daily 运行，不触发检索/模型/翻译。运行前保存简报和 state 备份，验证所有其他 Vault 文件哈希、手写区、数据库 stages/usage 不变。此工具会重新发起只读查询，应仅在确实需要验证时手动运行。
